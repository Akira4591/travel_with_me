# Travel With Me Design Refactor Plan

本文档定义项目从本地 MVP 走向可私测、可商业化产品的设计级重构方案。它不描述单个代码改动，而描述产品边界、架构分层、质量门槛、商业化路线和执行顺序。

## 1. 重构目标

Travel With Me 的核心定位保持不变：

> 在旅行开始前，把想去的地点组织成一条可理解、可调整、可分享的多日路线。

本轮设计重构要解决三个问题：

1. 文档体系从“功能堆叠”改为“产品决策体系”。
2. 工程路线从“能跑”改为“能私测、能迭代、能商业化”。
3. 差异化能力从“概念完整”改为“可验证、可落地、可收费”。

## 2. 项目阶段定义

| 阶段 | 名称           | 目标                                              | 准入标准                                 |
| ---- | -------------- | ------------------------------------------------- | ---------------------------------------- |
| S0   | 本地 MVP       | 单机完成路线规划闭环                              | 本地创建/编辑/分享可用                   |
| S1   | 工程可私测     | 能给真实用户试用，不轻易丢数据或崩坏              | 质量门禁全绿、安全风险收敛、移动端可用   |
| S2   | 差异化验证     | 证明 AI 导入、分享长图、3D 沙盘确实比竞品更有价值 | 有评测集、有可用 3D 交互、有分享传播闭环 |
| S3   | 商业化基础设施 | 可以登录、同步、分享协作、控制成本                | 用户系统、云端数据、权限、配额、监控齐备 |
| S4   | 付费产品       | 可以收订阅费或佣金                                | 权益体系、支付、合规、运营分析齐备       |

当前项目处于 S0 到 S1 之间：产品方向成立，但工程门禁、安全、数据可靠性、移动端和商业基础设施不足。

## 4. 产品设计边界

### 4.1 必须坚持

- 这是旅行前规划工具，不是实时导航工具。
- 地图用于理解空间关系，不替代导航 App。
- AI 导入用于把攻略变成可编辑行程，不直接替用户做不可解释决策。
- 分享能力是产品传播入口，不只是导出功能。
- 3D 沙盘如果继续投入，必须服务路线理解和标记协作，不能只做视觉展示。

### 4.2 必须避免

- 避免变成“地图 App 的弱复制品”。
- 避免让 3D 成为性能沉重但决策价值不明确的装饰。
- 避免把 AI 输出直接当事实写入行程。
- 避免把 localStorage 当成商业化主存储。
- 避免在用户系统、协作、支付没有准备好前承诺商业化可用。

## 5. 设计一致性检查

| 设计初衷      | 当前实现                       | 偏离程度 | 处理建议                                |
| ------------- | ------------------------------ | -------- | --------------------------------------- |
| 多日路线组织  | 已有 days/events/location 模型 | 低       | 保持 state.js 单一真源                  |
| 非导航定位    | 路线规划只做规划展示           | 低       | 增加“导出到导航 App”，不做实时导航      |
| 中文攻略导入  | 已接 DeepSeek + 高德匹配       | 中       | 建立真实攻略评测集，补失败可解释性      |
| 旅行手账分享  | Canvas 长图已完成基础闭环      | 中       | 强化分享样式、短链接、只读页            |
| 3D 可编辑沙盘 | 目前偏展示，交互未闭环         | 高       | 先验证 3D 标记/路线理解价值，再进付费墙 |
| 商业化产品    | 缺登录、同步、协作、配额       | 高       | 先做 S1/S3 基础设施，不急于支付         |

## 6. 工程质量门槛

从 S1 开始，每个可交付版本必须满足：

1. `npm run check` 通过。
2. `npm test` 通过。
3. 核心用户路径有浏览器级 smoke test。
4. 不引入新的未转义用户输入渲染。
5. 不扩大密钥暴露面。
6. 新增外部 API 必须有超时、错误提示、成本保护。
7. 文档同步更新。

当前第 1、2、3 项已有基础闭环；第 4 项仍需继续审计所有渲染点，第 6 项仍需补齐端点级测试和安全头。

## 7. 阶段化重构路线

### Phase A: 文档与质量基线

目标：把项目从“功能说明”整理为“可执行的产品工程计划”。

交付：

- 拆清文档职责。
- 将商业化方案从架构文档中降噪，保留为独立路线图。
- TODO 改成按 P0/P1/P2 和阶段组织。
- 明确质量门禁和发布检查表。

### Phase B: S1 工程可私测

目标：真实用户试用时不出现明显安全、数据、移动端问题。

交付：

- 修复 `npm run check`。
- 修复 `setStatus()` 等 XSS 风险。
- 给 AI/高德代理补基础限流和来源校验。
- 给 localStorage schema 加迁移或导出兜底。
- 完成移动端基础布局。
- 补 Playwright smoke test。

### Phase C: S2 差异化验证

目标：验证产品核心差异化是否真的成立。

交付：

- 建立 20-30 篇真实攻略评测集。
- 统计 AI 导入召回率、误提取率、day 准确率、note 有用率。
- 分享长图完成小红书/朋友圈可传播版式。
- 3D 沙盘完成最小可用交互：点击标记、长按轮盘、路线高程反馈。

### Phase D: S3 商业化基础设施

目标：账号、同步、分享协作、配额、监控齐备。

交付：

- 用户系统。
- 云端 trip/workspace 存储。
- 只读分享链接和复制到我的行程。
- AI 导入次数配额。
- 错误监控、成本监控、基础埋点。

### Phase E: S4 付费化

目标：形成可收费权益。

交付：

- Pro 权益边界。
- 支付与 webhook。
- 隐私政策、用户协议、数据导出/删除。
- 3D 沙盘或 AI 导入不限次作为付费锚点。

## 8. 商业化优先级判断

短期不要先做支付。原因：

- 用户还没有账号和云端数据，付费权益无法稳定绑定。
- AI 导入质量还没有评测，难以承诺“不限次”价值。
- 3D 沙盘还没有编辑与分享闭环，暂时不适合作为付费墙。

更合理的顺序：

1. 私测稳定性。
2. 分享传播能力。
3. 云端保存和只读分享。
4. AI 评测与体验修正。
5. 3D 可编辑沙盘。
6. 订阅。
