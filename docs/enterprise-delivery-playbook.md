# Enterprise Delivery Playbook

本文档把 Travel With Me 按互联网大厂项目开发流程重新组织：从机会判断、需求、设计、技术、开发、测试、安全、发布、运营到商业化，明确每一步当前进度、产物、门禁、后续动作和 Codex 执行方式。

## 1. 当前阶段定位

当前项目处于：

> **S0.7：MVP 功能已成型，但尚未达到 Alpha 私测门槛。**

理由：

- 核心功能已跑通：多路线、多日行程、地点搜索、路线规划、AI 导入、分享长图。
- 架构方向明确：Hono BFF、原生 ES Modules、state 单一真源、api/render 分层。
- 差异化方向明确：中文攻略导入、手账分享、3D diorama。
- 质量门禁已通过：`npm run check` 和 `npm test`（48 tests）全绿。
- 安全、数据可靠性、桌面端 Web 私测闭环、E2E、监控、云端同步、用户系统仍需补齐。

## 4. 当前阻断项

### 4.1 S1 Alpha 阻断项

| 阻断项                                    | 风险                       | 解决方向                                    |
| ----------------------------------------- | -------------------------- | ------------------------------------------- |
| `setStatus()` 等 innerHTML 审计未全量完成 | AI/用户文本可能注入 HTML   | 文本状态走 `textContent`，HTML 使用点白名单 |
| AI/高德代理已有限流仍需补齐安全头         | 成本和滥用风险             | bodyLimit、安全头中间件、端点级测试         |
| localStorage 旧 schema 丢弃               | 用户数据可靠性不足         | 导出/导入、迁移或重置前提示                 |
| 桌面端 Web 私测闭环未完整                 | 真实用户试用时核心路径不稳 | 宽屏编辑、地图联动、AI 预览、分享、3D 入口  |
| 缺浏览器 smoke test                       | 核心路径不可回归           | Playwright 覆盖启动/添加地点/分享/3D        |

### 4.2 S2 差异化阻断项

| 阻断项       | 风险             | 解决方向                                   |
| ------------ | ---------------- | ------------------------------------------ |
| AI 无评测集  | 无法量化导入质量 | 20-30 篇真实攻略标注                       |
| 分享只有长图 | 传播链路不完整   | 只读分享页、复制到我的行程                 |
| 3D 只偏展示  | 难成为付费价值   | 模式决策、TerrainModel、路线高程、标记交互 |

### 4.3 S3 商业化阻断项

| 阻断项     | 风险               | 解决方向                  |
| ---------- | ------------------ | ------------------------- |
| 无用户系统 | 无法绑定数据和权益 | Supabase Auth 或 Auth.js  |
| 无云端同步 | 无法跨设备和留存   | 云端 workspace/trip 文档  |
| 无监控埋点 | 不知道用户卡点     | Sentry/PostHog 或等价方案 |
| 无配额系统 | AI/API 成本不可控  | 用户级和 IP 级配额        |

## 5. 项目整理目标

用户提出的“规范化、简洁化、完整化、健壮化、模块化、立体化”对应以下工程目标。

### 5.1 规范化

目标：

- 所有文档职责单一。
- 所有功能有需求、设计、实现、测试、验收。
- 所有提交前质量门禁明确。

执行：

- 保持文档入口统一在 README。
- 每轮完成后更新 TODO 和相关设计文档。
- 使用 `docs/codex-self-prompts.md` 做自检。

### 5.2 简洁化

目标：

- 不堆无关功能。
- 每个阶段只有一个主目标。
- 每个模块职责清楚。

执行：

- S1 只做可私测，不做支付。
- S2 只验证差异化，不做完整商业化。
- 3D 先做路线理解价值，不做真实城市复刻。

### 5.3 完整化

目标：

- 用户核心路径闭环。
- 异常路径闭环。
- 文档、测试、部署、验收闭环。

执行：

- 补桌面端 Web 核心路径。
- 补浏览器 smoke test。
- 补数据导出/导入。
- 补分享只读页和复制能力。

### 5.4 健壮化

目标：

- 安全风险可控。
- 数据不轻易丢。
- 外部服务失败可降级。
- API 成本可控。

执行：

- XSS 修复。
- API 限流。
- 高程/AI/高德失败降级。
- localStorage schema 迁移或导出兜底。

### 5.5 模块化

目标：

- `main.js` 不无限膨胀。
- AI、路线、分享、3D 各自有清晰模块。
- render/api/state 边界不破坏。

建议拆分：

```text
js/flows/
  guide-import-flow.js
  route-planning-flow.js
  share-flow.js
  trip-edit-flow.js

js/render/3d/
  terrain-mode.js
  terrain-model.js
  terrain-animation.js
  camera-rig.js
  map-interact.js
  radial-menu.js
```

### 5.6 立体化

目标：

- 产品不是平面功能列表，而是“用户场景 + 数据模型 + 体验 + 工程 + 商业”完整体系。
- 3D 不是装饰，而是地形、路线、标记、交互、分享的立体能力。

执行：

- 用场景驱动 3D LOD。
- 用路线高程摘要体现地形价值。
- 用功能标记表达“路上需要注意什么”。
- 用分享图/3D 截图形成传播资产。

## 6. 标准工作流

每次后续迭代按以下流程走：

```text
1. 读阶段文档
   README.md
   TODO.md
   docs/design-refactor-plan.md
   docs/project-delivery-maturity-review.md

2. 判断阶段
   S0 / S1 / S2 / S3 / S4

3. 明确边界
   做什么
   不做什么
   影响哪些模块
   需要哪些验收

4. 执行
   文档任务只动文档
   代码任务先最小切片
   不回滚用户已有修改

5. 验证
   npm run check
   npm test
   必要时浏览器 smoke test

6. 同步文档
   README / TODO / ARCHITECTURE / docs/*

7. 汇报阶段推进
   本轮推动了哪个门槛
   还剩哪些阻断项
```
