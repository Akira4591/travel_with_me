# 2D 三层开发控制任务包

## 1. 控制目标

用“大层目标 → 中层功能包 → 小层执行任务”控制 2D 产品收口。每一层都必须先完成效果预览与问答确认，父层未确认时，子层保持阻塞，不进入产品实现。

本任务包只管理活动 2D 产品。`archive/3d/` 继续封存，不进入需求、设计、运行时、测试或发布范围。

## 2. 三层定义

| 层级     | 负责回答的问题                 | 必备产物                                              | 放行条件                     |
| -------- | ------------------------------ | ----------------------------------------------------- | ---------------------------- |
| 大层 `L` | 产品最终要形成什么整体体验     | 3 个总体效果方向、功能边界、取舍、确认记录            | 用户确认 1 个方向            |
| 中层 `M` | 已确认体验由哪些完整功能包组成 | 每个功能包的效果图、用户流程、数据/接口边界、验收标准 | 用户逐包确认                 |
| 小层 `S` | 每个功能包如何成为可验证的改动 | 文件范围、实现任务、测试任务、预期观察、回退点        | 前置包已确认且验收条件可执行 |

## 3. 状态机

```text
DRAFT -> IN_REVIEW -> CONFIRMED -> READY -> IMPLEMENTED -> VERIFIED
             |             |
             +-> REVISE <--+
```

- `DRAFT`：仅有任务定义，不可开发。
- `IN_REVIEW`：已提供 AI 效果图和功能描述，等待问答确认。
- `CONFIRMED`：用户已选定，允许展开下一层。
- `READY`：依赖、范围、验收和回退点齐备，允许实现。
- `IMPLEMENTED`：实现完成但尚未通过全部验证。
- `VERIFIED`：对应自动化证据和人工效果审查均通过。
- `REVISE`：根据反馈重做当前层，不连带扩展相邻范围。

## 4. 任务包模板

每个 `L/M/S` 任务包必须包含：

- `ID / 名称 / 状态 / 父包 / 依赖`
- `目标用户结果`
- `范围内 / 范围外`
- `效果预览或交互证据`
- `预期观察与验收标准`
- `文件或系统影响面`
- `验证命令或人工审查步骤`
- `失败回退点`

只为明确需求、已观察失败、既有不变量、安全边界或重大不可逆风险增加保护。禁止为假设场景提前堆叠兜底、重试、兼容层或新抽象。

### M1 · 工作区、路线与日期导航

- 父包：`L1-A`。
- 状态：`CONFIRMED`。
- 目标用户结果：用户始终知道自己正在编辑哪条行程、哪一天，并能在不丢失地图上下文的情况下切换、新建或回到全部日期。
- 范围内：顶部行程活页、当前行程状态、行程新增入口、日期导航、全部日期、日期新增入口、切换后的列表/地图上下文恢复。
- 范围外：地点编辑和地图加点（`M2`）、AI 导入（`M3`）、导入导出与分享（`M4`）、账号云同步、3D。
- 设计不变量：沿用已确认主页地图主导布局和当前主页美术；不引入第二套导航栏、侧边主菜单或移动 App 底栏。

### M2 · 地点时间线与 2D 地图联动

- 父包：`L1-A`；前置包：`M1-A`。

- 范围内：地点/路线选中态、列表与地图双向定位、地图路线高亮、地图搜索、候选地点预览、确认后的插入位置。

### M3 · AI 攻略导入、匹配与确认

- 父包：`L1-A`；前置包：`M1-A / M2-B`。
- 状态：`CONFIRMED`。
- 目标用户结果：用户把中文攻略转成候选行程后，能看清识别结果、已匹配地点和待处理歧义，并在明确确认后创建新行程。
- 范围内：城市与攻略文本输入、AI 解析/地点匹配进度、按天预览、标题/日期/时间/备注调整、删除候选、未匹配地点搜索绑定、确认创建新行程。
- 范围外：无确认自动写入、合并覆盖现有行程、模型或地图供应商切换、攻略社区、分享与工作区数据导入导出（`M4`）、账号云同步、3D。
- 设计不变量：保留当前主页美术、`L1-A` 地图主导布局、`M1-A` 双层标签和 `M2-B` 双向选中；解析或匹配失败不得修改现有行程，只有最终确认才创建新行程。

### M5 · 可访问性、桌面视口与移动兼容守门

- 父包：`L1-A`；前置包：`M1-A / M2-B / M3-A / M4-C`。
- 状态：`CONFIRMED`。
- 目标用户结果：桌面用户继续获得稳定的 `35/65` 行程与地图工作区；小屏用户在不横向溢出、不依赖隐藏手势的情况下查看同一行程和 2D 地图；键盘与辅助技术用户能辨认选中态、状态变化和模态边界。
- 范围内：`1280x800 / 1440x900 / 1920x1080` 桌面布局守门、`390x844` 基础兼容、行程/地图小屏查看模型、语义化控件和选中态、可见焦点、模态焦点与背景隔离、实时状态、`prefers-reduced-motion`、触控目标和页面横向溢出检查。
- 范围外：原生移动 App、移动端独立产品语言、移动底部主导航、离线模式、手势专属操作、账号同步、屏幕阅读器产品认证、3D。
- 固定验收不变量：桌面仍为顶部活页与左 `35%` / 右 `65%`；小屏只是兼容守门；所有核心操作有语义化按钮或标签、可见焦点和至少约 `44px` 的触控目标；模态打开时焦点受控且背景隔离；状态变化可被礼貌播报；减少动态偏好生效；页面不得产生整体横向滚动；选中地点在行程与地图之间保持同一关系。
